# MVP-1 演示脚本（8 分钟）

> 目标：让看的人相信"这条链路是真的"，而不是界面好看。
> 每条都给出**可核对的东西**：数字、分数、原因、403。

## 0. 开场（30 秒）

打开 `start.bat`，浏览器停在登录页。一句话：

> 这一版只做一件事：**简历进来，按岗位条件算清楚谁够格，并且说得出为什么**。
> 测评、培训、RAG、问数、Agent 编排都还没做，菜单里能看到，点进去是空态——不假装能用。

## 1. 用 HR 登录（`hr_zhao` / `123456`）

看点：侧栏只有 4 个菜单（工作台/简历/岗位条件/岗位匹配），底部写着「人力资源部 · 本部门」。
→ 说明权限不是装饰，菜单是按角色下发的。

## 2. 工作台（1 分钟）

- 顶部 4 个数字：简历总数、已解析、队列待处理、最近岗位通过率。
- 解析队列：排队/解析/待 OCR/失败四个格子。**待 OCR 有 1 份**（那是上传的图片简历）。
- 当前岗位匹配：通过 2 人、平均分、通过率，下面 5 行名单。

一句话：**这页不做图表**，因为它要回答的是"有没有东西卡住"，不是"趋势好不好看"。

## 3. 上传并解析（2 分钟）

1. 点「上传简历」→ 拖入 `samples/` 里的 PDF/DOCX/TXT（可选绑定岗位）。
2. 上传后自动逐份解析，等待 2–3 秒。
3. 回到列表：3 条新记录，姓名/学历/年限/技能都在。

看点：打开任一条「查看」→ 右侧抽屉里是**抽取字段 + 简历原文 + 解析日志**。
改一个字段（比如把年限从 5 改成 6）→ 保存 → 记录上出现「已人工校对」。

一句话：**规则解析一定会错，所以给了人工修正的口子**；修正只改档案，要重新匹配才改分。

## 4. 岗位条件（1.5 分钟）

点「岗位条件」：

- 左表：岗位、硬条件、权重、合格线。
- 右栏「条件试算」：选中哪个岗位，就用它对你可见的简历**实时试算**，给出分数分布和通过人数。

点「编辑」看编辑抽屉：硬条件（学历/技能/年限）+ 五维权重滑块 + **画像能力基线**（技术深度/工程能力/业务理解/协作沟通/成长性）+ 合格线。

抽屉最下面那块「画像能力基线」是新增的：填了基线的维度，匹配时按「实际能力 ÷ 基线」打分，占的是「档案完整度」那 10% 的席位。
拖动任一基线滑块，会自动把最大权重匀 10 给「画像契合」，可再手动调。

一句话：**改权重只影响下一次匹配**，历史结果带着当时的快照，永远能复现。

## 5. 匹配（2 分钟）

点「岗位匹配」：

1. 选「高级算法工程师(AI平台部)」→ 点「开始匹配」。
2. 顶部 4 个数字刷新：已匹配 5、通过 2、未通过 3、平均分。
3. 表格按分数从高到低，**分数条上的竖线就是合格线**——一眼看出谁过线、差多少。
4. 点任一条「查看」进详情。

一句话：通过 2 人（张伟 85、陈宇 81），未通过 4 人——张伟的「画像契合」100 分，两项能力都超过基线。

### 5.1 测评反哺（1 分钟，四块闭环的最后一环）

1. 「智能测评」里点「开始答题」，用张伟的身份答完（或直接看已有的第 3 次提交）。
2. 回到「人才画像」点张伟 → 抽屉底部「测评证据（反哺）」：技术深度 简历 100 / 测评 87 → 96，业务理解 简历 32 / 测评 0 → 29。
3. 再回「岗位匹配」重跑一次 → 画像契合读的是新分数（技术深度 96、工程能力 88，都在基线之上）。

一句话：**测评不是孤立的考试，它会把画像里的分数改掉，进而改掉匹配结论。**

## 6. 可解释性（1.5 分钟）—— 这是重点

进详情页往下看「画像基线对照」：工程能力 87/85、技术深度 100/90，每行带进度条和「达基线 / 差 x%」。
这一块直接回答「凭什么说他行」——不是一句综合评语，是逐维数字。

在详情页：

- 左侧：结论（通过/未通过）、高出/低于合格线多少分、**五维得分构成**（学历/技能/年限/项目/完整度）+ 权重快照。
- 右侧：「判定理由」是一段能逐条对上的话，例如
  `学历 硕士 达到要求 硕士（92 分）；技能命中 PyTorch、Python，覆盖率 3/5（64 分）…综合 80 分，达到合格线 70。`
- 未通过的例子（王峰 vs 算法岗）：`不匹配：技能（未命中 PyTorch）；学历 本科 低于要求 硕士…综合 27 分，未达合格线 70。`
- 下方：「硬条件判定」逐条打勾/打叉。

一句话：**没有黑箱**。任何一个分数都能倒推回字段和规则。

## 7. 权限（1 分钟）—— 第二个重点

换 `pm_wang`（业务负责人）登录：

- 侧栏只剩工作台 + 岗位匹配；点「简历智能筛选」→ **403 无权限：resume:view**。
- 匹配页能看，但「开始匹配」按钮不可点（只有 `match:create` 才能执行）。

换 `emp_chen`（普通员工）：只有工作台，其他全 403。

一句话：**三层都拦**——菜单权限、接口权限、行级数据范围（HR 只看本部门）。

## 8. 收尾（30 秒）

打开终端跑三条命令（或提前跑好贴结果）：

```bat
python scripts\smoke_test.py     :: 17/17 接口与权限断言
python scripts\eval_match.py     :: 判定 5/5 · 分数区间 5/5 · 原因关键词 5/5
python scripts\init_db.py --check :: seed 夹具核对
```

一句话：**每次改动都跑这三条**，不是演示前临时凑的。

## 常见提问与回答

| 问 | 答 |
|---|---|
| 准确率有 99% 吗？ | 没有。规则解析在中文简历上约 60–75%，所以做了人工修正；要冲 99% 得接大模型兜底（MVP-2），并且先把 99% 的口径定义成"关键字段 F1" |
| 能并发 2000 吗？ | 这一版没压测，不敢说。架构是异步的，但缓存层/连接池没调优 |
| 为什么不用 Milvus？ | 这一版匹配是硬条件 + 特征打分，不需要向量召回；接口留了，MVP-2 做语义检索时再装 |
| 匹配分为什么这么低（未通过 26–27）？ | 硬条件不满足时按规则折算到合格线下，但**不隐藏分数**，并在原因里点名差在哪 |
| 改权重会不会影响历史结果？ | 不会。结果里存了当时的权重快照 |
| Admin 能看到全部吗？ | 能，`data_scope=all`；HR 只看本部门 |
