# S3 交付说明 · 身份去重

> 完成时间：2026-11-04 12:20 ｜ 对应需求：② 同一人两份简历，优先采用最新，老简历可丢弃
> 配套：`后端优化项-TODO.md`（S3 已全勾）

---

## 1. 一句话

**同一人的多份简历只留最新一份在列表/匹配/画像里，旧的不删只标"已被替代"；同名但手机号不同的人绝不合并。**

---

## 2. 判定口径（这是本阶段最关键的决策）

| 优先级 | 判据 | 自动合并 | 理由 |
|---|---|---|---|
| 1 | **手机号相同**（归一化后） | ✅ 是 | 手机号是强唯一标识 |
| 2 | **邮箱相同**（小写归一化） | ✅ 是 | 同上 |
| 3 | 姓名 + 学历 + 专业 全同 | ❌ **不合并**，只报"疑似" | 两个"张伟"都可能是硕士计算机，误合并会丢人 |
| — | 只有姓名相同 | 不处理 | 重名太常见 |

**"最新"的口径：按自增 id 倒序**（id 越大 = 越后插入 = 越新）。

> 为什么不用 `created_at`：`server_default=func.now()` 在 `flush()` 后**不会回填到 ORM 对象**，新插入行的 `created_at` 在本次事务里是 `None`，会被误判成"最旧"。这个坑实测踩到了（见 §6）。

**归一化规则**：
- 手机号：去空格/横线/括号/`+86`/`0086`，取纯数字，≥7 位才算有效
- 邮箱：小写 + trim，必须含 `@` 且域名带 `.`

## 6. 实施中撞到的三个真问题（都修了）

### 6.1 `created_at` 排序失效

第一版用 `created_at` 倒序判定谁新，结果**新版被判成旧版**。

根因：`SessionLocal` 是 `expire_on_commit=False` + `server_default=func.now()`，新插入行的 `created_at` 在 ORM 对象上是 `None`。

改成按自增 `id` 倒序（语义等价，且不依赖数据库回填）。

### 6.2 `autoflush=False` 导致查不到自己

第二版仍失败：`reconcile_identity` 里设了 `parsed.identity_key = key`，紧接着按这个键查库，但 `SessionLocal` 是 **`autoflush=False`**，改动还在内存里没写进库，**查不到自己** → 把自己判成"旧版"。

修复：设置键后显式 `db.flush()`。

### 6.3 向量库残留陈旧向量

去重后旧简历不再被索引，但**旧向量还留在 Milvus 里**。结果：

```
resume_count = 8（库里只有 6 份现行）
expected_count = 6
stale = True   ← 永远为 true
```

导致 `reindex-if-stale` **每次判定"过期"并全量重建**，幂等失效（测试 `s1_vector_test` 从 11/11 掉到 10/11）。

修复：新增 `prune_stale_vectors()`，`index_resumes` 写入后自动按主键差集删除陈旧行。实测 `pruned: 2`。

## 8. 顺带处理的一件事：`init_db --reset` 会清空演示数据

为了验证 `seed_data.sql` 能原样加载，我跑了 `init_db.py --reset`。它只加载 seed（3 题 / 2 课 / 1 错题），而回归测试需要 12 题 / 5 课 / 有错题。

新增 `scripts/seed_demo_extra.py` 固化补齐逻辑（幂等）：

```
题目 +9（题库共 12 题）；课程 +3
课程挂考核 +2
```

**以后每次 `init_db --reset` 后跑一次这个脚本即可恢复演示数据。**

## 10. 前端对接要点

| 场景 | 怎么做 |
|---|---|
| 简历列表 | 默认不用传参，后端已只返回现行；需要看历史时传 `?include_superseded=1` |
| 列表项标记 | `is_current=false` 的项加「已被新版本替代」徽标，点击跳到 `superseded_by` |
| 详情页 | `identity.siblings` 渲染成时间轴，标出哪份是现行 |
| 疑似重复 | `GET /identity/suspected` 出提示条「发现 N 组疑似重复，建议人工核对」，**不给自动合并按钮** |
| 上传后 | 解析响应里带 `identity`，可提示「该候选人已有旧简历，已自动采用新版」 |

## 11. 已知边界

1. **"最新"按 id，不按简历里的最近工作时间**：要按工作时间需给解析器加字段，属额外一轮。
2. **旧简历不删，只标 `is_current=0`**：文件与解析结果保留可追溯；真要删需另做清理接口。
3. **疑似重复只报不合并**：`/identity/suspected` 只返回组，合并动作不在本期范围。
4. **没有可靠身份的简历**（无手机号无邮箱）各自独立，永不被替代。
5. **`prune_stale_vectors` 每次全量重建时都会跑**：简历量大时是一次全表 query + 一次 delete，MVP 规模无感，后续可优化为只删差集。
