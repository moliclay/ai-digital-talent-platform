# S5 交付说明 · 转正建号 + 员工只有培训成长

> 需求⑤ ｜ 完成 2026-11-04 ｜ 回归 `s5_onboard_test.py` **25/25**

## 1. 需求原文

> 还有的题库就是面向企业员工的，HR 操作候选人将其转为正式员工后，该员工就会以手机号加一个初始密码创建一个账号，登录为员工身份，员工的功能只有培训成长。

## 2. 建号流程

```
POST /api/resumes/{id}/onboard   (resume:edit)
{ "department_id": 4, "department_name": "算法组", "initial_password": "" }
```

| 步 | 校验 | 失败 |
|---|---|---|
| 1 | 简历存在且当前用户可见 | 404 / 403 |
| 2 | 幂等：已有 `employee_user_id` | 409 + 返回已有账号 |
| 3 | 手机号存在且归一化后 ≥11 位 | 400「请先在简历详情补全 11 位手机号」 |
| 4 | `sys_users.username` 未占用 | 409「手机号已被账号 xxx 占用」 |
| 5 | 建号：`username=手机号, real_name, phone, department_id` | — |
| 6 | 绑 role 4（employee） | — |
| 7 | 回写 `employee_user_id` / `onboarded_at`，同步画像 | — |
| 8 | 写 `sys_operation_logs` 审计 | — |

**初始密码**：`Emp` + 6 位随机数字（共 8 位，便于口头转述）。
**只在响应里返回一次**，不落库明文、不写日志。

## 3. 员工权限重配

| 菜单 | 原来 | 现在 | 理由 |
|---|---|---|---|
| 1 智能工作台 `dashboard:view(self)` | 有 | **收回** | 员工不该看招聘数据 |
| 5 培训成长 `train:view` | **无** | **授 `view(self)`** | 需求「员工的功能只有培训成长」 |
| 5 培训成长 `train:edit` | 无 | **授 `edit(self)`** | 员工要能点「完成学习」 |
| 7 知识库 `kb:view(self)` | 有 | **收回** | 无对应接口，留着只进空态 |

收回 dashboard 后，`menus` 只剩培训成长，落地页自然落到 `/training`，不用改落地逻辑。

`init_db.ensure_permissions` 增加了 revoke 逻辑，重跑 `init_db` 不会把收回的权限又加回去。

## 4. 员工自助接口

| 接口 | 作用 |
|---|---|
| `GET /api/my/training/summary` | 计划数 / 任务进度 / 待办 / 台账条数 |
| `GET /api/my/training/plans` | 我的培养计划（含任务明细） |
| `GET /api/my/training/ledger` | 我的成长台账 |

解析路径：`user.id` → `parsed_resumes.employee_user_id` → `parsed_resume.id` → `prejob_plans.candidate_id`。
**未转正返回 `onboarded: false` + 空列表，不是 404**（前端好做空态）。

## 5. 越权校验（本阶段最重要的安全项）

### 5.1 任务操作

授了 `train:edit(self)` 后，原 `tasks/{id}/progress|complete|assess` 只校验权限码 →
**员工能改任何人的任务**。加归属链校验：

```
task.id → task.plan_id → plan.candidate_id
        → parsed_resumes.employee_user_id → 比对 user.id
```

非 admin/HR 且不匹配 → **403「无权操作该任务」**。

### 5.2 查询类接口（更宽的越权面）

员工拿到 `train:view(self)` 后，这些都能查别人：

| 接口 | 越权方式 |
|---|---|
| `GET /training/diagnose?candidate_id=1` | 换 candidate_id |
| `GET /prejob-plans` | 不带过滤即全量 |
| `GET /prejob-plans/{id}` | 换 id |
| `GET /training/ledger?candidate_id=` | 换 candidate_id |

统一加 `_assert_candidate_scope(db, user, candidate_id)`：员工只能传自己的 candidate_id，不传则强制为自己的。

## 8. 已知边界

- 初始密码不落库，**HR 关掉弹窗就再也拿不到**——如需重置，走系统用户的重置密码接口（admin 权限）；
- 员工无法自助答题（本期 HR 代答）；
- 员工的 `self` 数据范围是 service 层校验，不是数据库行级安全（RLS）。
