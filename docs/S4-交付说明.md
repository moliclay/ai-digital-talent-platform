# S4 交付说明 · 题库两套受众 + HR 绑定 + 简历显示「已测评」

> 需求④ ｜ 完成 2026-11-04 ｜ 回归 `s4_assignment_test.py` **27/27**

## 1. 需求原文

> 题库方面，有一套题库是面向候选人的，HR 先将题目与候选人绑定，目前直接由 HR 代答题就行，答完题后简历列表就会显示一条数据：已测评。

## 2. 拆解

| 子项 | 做法 |
|---|---|
| 题库分两套 | `question_banks.audience` + `exams.audience`，值 `candidate` / `employee` |
| HR 绑定题目给候选人 | 新表 `exam_assignments`（简历 × 试卷 × 状态） |
| HR 代答 | 沿用 `POST /api/exams/{id}/submit`，新增 `assignment_id` 参数回填 |
| 简历列表显示「已测评」 | `exam_summary` 三态字段，批量查询避免 N+1 |

## 3. 表变更

```
question_banks   + audience VARCHAR(32) NOT NULL DEFAULT 'candidate'
exams            + audience VARCHAR(32) NOT NULL DEFAULT 'candidate'
exam_submissions + parsed_resume_id INT NULL  (+索引)

新表 exam_assignments:
  id / exam_id / parsed_resume_id / candidate_name
  status(pending|submitted|cancelled) / submission_id
  assigned_by / deadline / note / created_at / updated_at
```

默认 `'candidate'` 的两个理由：历史数据全是候选人卷；`seed_data.sql` 原样加载不受影响。

## 4. 状态机

```
        bind                submit
  ∅ ──────────► pending ──────────────► submitted
                   │
                   │ cancel
                   └────────────► cancelled
```

| 操作 | 允许状态 | 冲突处理 |
|---|---|---|
| bind 同一「简历×试卷」 | 已有 pending | 幂等返回 `existed` |
| bind 已有 submitted 的 | 允许 | 新建 pending（支持重考） |
| submit | 仅 pending | submitted/cancelled → **409** |
| cancel | 仅 pending | submitted → **409** |

## 5. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/exam-assignments` | `exam:create` | 单条 `parsed_resume_id` 或批量 `parsed_resume_ids` |
| GET | `/api/exam-assignments` | `exam:view` | 按 `parsed_resume_id`/`exam_id`/`status` 过滤 |
| DELETE | `/api/exam-assignments/{id}` | `exam:create` | 置 cancelled，不物理删 |
| GET | `/api/question-banks?audience=` | `exam:view` | 按受众过滤 |
| GET | `/api/exams?audience=` | `exam:view` | 按受众过滤 |
| POST | `/api/exams/{id}/submit` | `exam:view` | 新增 `assignment_id` |
| POST | `/api/exams` | `exam:create` | 不传 audience 时从 `bank_ids[0]` 继承 |

## 6. exam_summary 三态

```json
"exam_summary": {
  "state": "none | assigned | submitted",
  "label": "未测评 | 待测评 | 已测评",
  "total": 1, "passed": 1,
  "items": [{exam_id, exam_name, audience, state, assignment_id,
             submission_id, score, max_score, pass_score, passed, deadline, submitted_at}]
}
```

`submitted` 优先于 `assigned`：同一简历既有已提交又有待答的卷，徽标显示「已测评」，明细里两条都在。

**性能**：`summaries_for(resume_ids)` 一页 N 条只查 2 次库（assignments 一次、submissions 一次），内存分组。

## 7. 实测输出

```
★ 绑定试卷给候选人 — created=1
★ 绑定后列表显示「待测评」 — state=assigned label=待测评
★ 带 assignment_id 提交成功 — score=100/100 passed=True
★ 答卷回填 parsed_resume_id — parsed_resume_id=3 expect=3
★ 绑定状态变 submitted 并记 submission_id
★ 提交后列表显示「已测评」 — state=submitted label=已测评
已提交的绑定不能重复提交（409）
已提交的绑定不能取消（409）
批量绑定 3 人 — created=3
重复绑定同一对 — existed=1（幂等）
```

## 9. 已知边界

- 绑定关系只支持「整卷」绑定，不支持按题绑定（需求原文是「题目与候选人绑定」，实现为整卷绑定，因为答卷按卷提交）；
- 已取消的绑定不参与 `exam_summary`；
- 学员端（员工）答题未做，本期仍是 HR 代答。
