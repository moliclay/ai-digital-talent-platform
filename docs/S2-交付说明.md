## 1. 一句话

**查重、语义检索、岗位召回三处现在返回同一种"简历摘要"，都带 `parsed_resume_id`，前端点任一条都能直接调 `GET /api/resumes/{id}`。**

---

## 2. 统一的数据结构 `brief`

```json
{
  "parsed_resume_id": 1,
  "resume_file_id": 1,
  "name": "陈宇",
  "education": "硕士",
  "major": "计算机科学",
  "years_experience": 5,
  "skills_top": ["Python", "PyTorch", "NLP", "分布式"],
  "skills_count": 4,
  "filename": "陈宇_算法.pdf",
  "created_at": "2026-11-02 18:25:54",
  "accessible": true
}
```

- `parsed_resume_id` = 详情接口的唯一入口
- `accessible` = 当前用户能否打开详情
- `skills_top` 只给前 5 项（原来 22 项串成一坨，列表塞不下）
- `skills_count` 给总数，前端可以显示"技能 22 项"

## 3. 三个接口的变化

### 3.1 查重 `GET /api/resumes/duplicates`

**之前**：`{a_id, a_name, b_id, b_name, similarity}` —— 只有名字，前端无法判断"这是哪一份"。

**现在**：

```json
{
  "similarity": 0.7751,
  "a": { ...完整 brief... },
  "b": { ...完整 brief... },
  "a_name": "陈宇", "b_name": "张伟",
  "a_id": 1, "b_id": 4
}
```

保留 `a_id/b_id/a_name/b_name` 是为了**旧前端不改也能跑**；新前端用 `a` / `b`。

### 3.2 语义检索 `GET /api/resumes/semantic`

`{...brief..., "score": 0.4346}`

### 3.3 岗位召回 `GET /api/job-profiles/{id}/semantic-candidates`

`{...brief..., "similarity": 0.6398}`

## 4. 一个做了改动的设计决策（和原方案不同）

原方案写的是"`accessible=false` 的条目不剔除，只标出来让前端置灰"。**实测发现问题**：

```
dept 范围用户查重 → pairs = 9
  陈宇 accessible=False | 张伟 accessible=False
```

全部 9 对的两侧都不可访问，但姓名照样返回了——**这是越权泄露**：一个只看本部门的 HR，能通过查重接口看到别的部门所有候选人的姓名和学历。

改成：

| 情况 | 处理 |
|---|---|
| 双方都可访问 | 保留 |
| **只有一方可访问** | 保留，不可访问那方标 `accessible=false` 置灰（"这两份像"的语义要完整） |
| **双方都不可访问** | **整对丢弃** |

实测修复后：dept 范围用户查重 `pairs = 0`（示例简历都在部门 1），不再泄露。

## 7. 前端对接要点

| 场景 | 怎么做 |
|---|---|
| 查重列表 | 每条展示 `a` 与 `b` 两张小卡（姓名/学历/专业/年限/技能前5/文件名），中间显示 `similarity` 百分比 |
| 点任意一侧 | `navigate('/resumes/' + brief.parsed_resume_id)`；`accessible=false` 时置灰不可点，并提示"无权查看" |
| 语义检索 | 列表项展示 brief + `score`（相似度百分比），点进详情同上 |
| 岗位召回 | 同上，字段名是 `similarity` 不是 `score` |
| 技能展示 | 用 `skills_top` 渲染 chips，末尾加 `+N`（N = `skills_count - 5`） |

## 8. 已知边界

1. **`created_at` 是解析入库时间**，不是简历里的最近工作时间（S3 讨论"最新简历"时会再碰这个口径）。
2. **查重仍只报不合并**：返回成对结果，合并动作不在本期范围（原三项增强之一）。
3. **`brief_of` 的 `accessible` 在 `user=None` 时恒为 true**：内部调用（如向量索引）不需要权限判断时用默认值，对外接口一律传 user。
4. **查重的 N+1 已消除**：所有 brief 走一次 `IN` 查询（`briefs_by_ids`）。
